# 偏好记忆与对话恢复

## 用户可见行为

- “记住，我爱吃穷鬼套餐，喜欢无糖饮料”：记录明确口味。首次可以没有门店。
- “穷鬼套餐”/“一加一”/“随心配”：使用1+1超值系列别名，再匹配当前真实菜单；没有对应商品时如实说明。菜单价格和官方算价各自展示，不硬编码某个活动价。
- “今天要普通可乐”：本次要求优先于无糖默认，不反过来永久修改习惯。
- “我的偏好”“忘记无糖”“清除偏好”“关闭记忆”“开启记忆”：随时管理，不触发订单操作。
- 餐品被多次明确选择后形成较弱的推荐信号，标明“选择次数”，不冒充付款或消费次数。

## 保存范围

`scripts/dining_memory.py` 使用项目 `runtime/dining-memory.sqlite3`，权限600，以操作者散列隔离。保存有限的饮食标签、已验证目标的自定义别名和餐品选择统计。模型不能直接改记忆。不保存完整聊天、精确位置、账户ID、卡包券码、手机号、健康情况或凭证；不读取官方常点画像或历史订单。测试使用各自临时确认库旁的独立偏好库。

微信和网页的操作者分别隔离，不通过猜测把网页访客合并为绑定微信。微信页的管理操作明确针对当前绑定者。

原版对话上下文漏掉助手回复、快捷命令及按钮操作。现改为每次会话保存最近8条用户/助手上下文、当前已选餐品和待补充城市的查询。只在内存中维护最近20轮脱敏对话；微信页按需查看，重启清空，无法补读以前没有存储的聊天。账户查询结果不放进模型上下文。

## 已复现错误与恢复

门店查询失败后，旧版对话可能只返回模型生成的重试承诺，却没有实际查询结果。以下仅描述错误机制，不保留个人故障对话或真实地点。

`query-nearby-stores` 只带 `searchType=2/beType=1/keyword`、缺少city时可能返回 `success=false, code=600058`；补充有效城市后再查询候选。虽然实时 schema 未将city列入required，客户端必须补齐城市。缺失时只追问城市并保留想吃的餐品，用户回复城市后实际执行查询。测试使用合成门店名“示例广场店”。

`OrderingAgent._query` 区分查询阶段，记录有限的待重试只读操作。“重试”真正执行该查询；不自动循环、不重放写请求。模型的question里出现“我帮您重新查”等未执行承诺时采用本地澄清文案。所有下单仍受当前预览和确认台账约束。

## 麦当劳账户

MCP Token 来源于官方平台登录/激活后的授权账号，个人微信扫码只是消息入口。有效Token通常不用在本地重复登录；付款页可另要求验证。切换微信不等于切换麦当劳账号，变更麦当劳账号需更新相应Token。

“账号说明”只解释机制，不读取资产。“我的积分”调用 `query-my-account`；“我的优惠券”调用 `query-my-coupons`，只展示必要信息，不显示账户ID和券码，不声称卡包券必然适用于当前门店。已发现的工具中没有用于取得完整个人资料/手机号/会员等级的专用工具。公开测试仅使用模拟账户，不包含个人资产与账户标识。

## 界面约定

沿用现有红色 #C82028、黄色 #FFBC0D、纸白 #FFFFFF、浅灰 #F4F5F7 与墨色 #242424，中文系统字体。微信页保持原连接流程，下面以现有设置分区展示偏好摘要和管理按钮；最近对话折叠在同一区，不另造第二个点餐入口。手机改为单列，长文本可断行，所有对话用textContent渲染。

本机后台的 `/api/weixin/recent` 只返回当前绑定者的内存对话和偏好；`/api/weixin/memory` 必须经过本机来源校验，只支持启用、停用和清除。公开定位监听器不开放这些路由。
