# 个人微信点餐智能体

依据腾讯维护的 https://github.com/Tencent/openclaw-weixin 和 docs/protocol.md。参考包 @tencent-weixin/openclaw-weixin@2.4.10 已做 npm SHA512 核验，源码在 runtime/weixin-source/。本项目为 Python 协议兼容桥接，不是腾讯认证应用或全局 OpenClaw 安装。

## 点餐

微信与网页共用 ordering_agent.py；千问／DeepSeek 在 /settings 配置一次，两端实时生效。默认一位、预算可选。门店、菜单、选配、算价、下单都走麦当劳 MCP。

例：“定位” → 单次链接授权 → 回微信“选店1” → “推荐牛肉套餐，饮料无糖” → “套餐1” → “堂食” → 查看门店、搭配、官方金额 → “确认下单”。返回待支付订单和官方 payH5Url；本人付款后发“订单状态”查取餐码。

模型不能调用写工具或把历史确认当本轮授权；服务端只接受当前真实预览的明确确认，并再次算价。没配模型时支持明确指令，不假装理解所有说法。

## 定位

公开 MessageItem 没有可直接使用的原生位置字段，不声称可直接读取手机 GPS。设置页启用独立 HTTPS 通道后，微信发“定位”拿单次链接。

端口8766只提供令牌保护定位页及静态资源，没有设置、麦当劳接口或文件浏览路由。Cloudflare 隧道只代理此端口，禁止代理8765。随机令牌只存内存哈希，绑定 owner 的会话，单次使用、5分钟到期；同 owner 新链接使前一个失效。POST 验证 Origin、路径、请求大小和坐标范围。

只在用户点授权后发坐标，Photon（备用 Nominatim）用 OpenStreetMap 数据解析地址，坐标不落盘。门店由用户选择，不能自动在搜索第一家下单。

## 协议与身份

- 默认 https://ilinkai.weixin.qq.com，POST 用公开头及独立 bot 凭证，只接受微信域内 HTTPS 服务地址。
- 扫码 get_bot_qrcode / get_qrcode_status；接收 getupdates 长轮询。
- 只响应绑定 owner 的非群新消息，拒绝其他人、错误收件人、旧消息、缺 context_token 的消息；回复沿用原上下文。
- 不主动欢迎、不联系别人。每条消息先做 SQLite 哈希声明，避免重复处理。只用已转写语音，不下载音频。
- 回复发送结果未知不自动重发。订单提交未知由独立台账跨重启锁定，重复微信消息不能再次创建。

## 数据与可用性

凭证、游标、去重在 runtime/weixin/，目录700、文件600；不记原始聊天、context_token 或完整身份日志。对话和菜单只存进程内，已知订单号留在确认台账。

连接页可暂停／恢复／删除绑定。重启默认暂停；手机端解绑另在微信操作。电脑需在线；临时 HTTPS 地址受网络和 Cloudflare 可用性影响，不当作生产固定域名。只接绑定者一对一，不宣称群机器人、群卡片或共享账户。
