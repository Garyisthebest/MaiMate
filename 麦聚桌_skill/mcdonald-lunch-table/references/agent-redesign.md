# 麦聚桌：到店即点餐

2026-10-24 的重构以个人微信为主入口，网页提供同一智能体的聊天、定位和连接设置。

## 用户路径

1. “我到店了，想吃牛肉，饮料无糖。”定位可用时查附近门店，否则只问门店名；人数默认一位、预算可选。
2. 读取真实菜单和套餐详情，给少量有区别的推荐；选配只能使用当前详情中的编码，不由模型编造。
3. 选择套餐、替换饮料，官方算价，展示门店、商品、套餐子项、取餐方式和最终金额。
4. 回复“确认下单”创建待支付订单，返回官方收银台。模型不能代替用户授权扣款。订单状态和取餐码来自官方查询。

模型支持千问／DeepSeek 的兼容接口，API key 只留在本项目。自然语言理解与业务执行分离；选项和最终金额由服务端验证。未填模型 key 时保留明确命令模式，并在界面如实显示。

## 界面方向

主体是聊天与当前订单，移除人数表格和预算检查流程。红 #C82028 为动作色，黄 #FFBC0D 为订单标识，纸白 #FFFFFF、浅灰 #F4F5F7、墨黑 #242424；中文系统无衬线正文，订单数字保持清晰。手机单列、电脑聊天与窄订单栏，门店和选配按钮直接插入对话。设置只显示连接与密钥状态。

## 已核实边界

- 当前账户门店工具只接受 searchType=1/2、city、keyword，没有经纬度字段；不得虚构 searchType=3。浏览器定位需先反向地理编码，再按城市和地标查真实门店。
- 当前个人微信协议公开文字和已转写语音，未提供原生位置消息字段；不得声称可以暗中读取手机 GPS。支持门店名及单次定位链接；手机定位链接需要可访问的 HTTPS 公网地址。
- 创建订单返回 payH5Url，未公开代扣 API；“选餐即支付”实现为选择、确认后创建订单并跳转官方支付。
- 沿用本地确认台账、价格复核与未知结果锁定。未获得具体订单确认时只查询，不执行真实消费测试。

## 2026-10-24 验证记录

- 80项 pytest 通过；覆盖无预算点餐、真实编码选配、无糖要求、模型工具调用约束、价格变化、过期预览、重复确认、未知提交跨会话／重启锁定、定位链接单次使用、公开监听器路由隔离。
- 真实 MCP 发现35个工具；用公开上海测试坐标完成 Photon 地址解析、真实门店搜索、菜单推荐、5组选配解析、官方算价及确认预览。停在提交前，没有创建订单或付款。
- Playwright 使用本项目 Conda 环境及本机 Chrome；1440、768、390宽度通过，未出现横向溢出或 JavaScript 错误。完整下单、付款链接和取餐码链路在隔离模拟服务器执行，未对真实账号写入。
- Cloudflare 官方组件安装在项目 runtime/bin，SHA256对应官方 release；HTTPS通道已连通，公开域名的 /api/settings 返回404。它只代理独立的单次定位接收器。
- 千问／DeepSeek尚未提供真实模型key，已验证兼容请求、结构化返回与密钥隔离；真实模型联调需要用户在 /settings 填key并测试。现有微信绑定保留，升级重启后默认暂停，需恢复接收；新点餐链路的真实微信收发仍待用户主动消息验证。

## 2026-10-24 DeepSeek 微信 HTTP 400 修复

用户配置 deepseek-flash 后，普通文本连接测试通过，但实际点餐的强制工具调用返回 HTTP 400。已复现思考模式与 tool_choice 冲突，DeepSeek 结构化点餐请求增加 thinking.type=disabled；千问请求保持原参数。

连接测试改用与微信相同的 order_intent 请求和本地 schema 校验，拒绝仅返回普通文本、非法意图或写工具的响应。HTTP 错误使用固定本地分类文案，不再把请求参数不兼容统一提示为检查密钥。

92 项 pytest 通过，新增供应商参数差异、工具调用能力测试及错误信息不泄露回归。使用用户已配置的 DeepSeek 真实接口验证结构化测试和上海人民广场鸡肉套餐需求解析，返回正确 search 意图；未创建订单、付款或主动发送微信测试消息。
