# 麦聚桌：你的点餐搭子

核心是“到店，说一句想吃什么，选餐后去官方付款”。个人微信是日常入口；网页使用同一个点餐引擎，并负责模型设置、定位和订单展示。人数默认一位，预算可选，不强迫填写预算表格。

项目根是此目录的父目录。所有代码、配置、依赖、下载、缓存、凭证及测试输出留在项目内。使用项目 .conda/bin/python 或 ./run.sh，不修改全局配置。不读取或展示 .env 中的 Token。

## 执行路径

1. 先读 [official-integration.md](references/official-integration.md)，按实时 tools/list 校验参数。MCP 固定地址 https://mcp.mcd.cn，Streamable HTTP，Bearer，协议2025-06-18。到店取餐 beType=1、orderType=1，不传 beCode。
2. 启动 ./start-preview.sh。网页 /settings 填千问或 DeepSeek key，立即生效；模型只输出受 schema 约束的意图，不能直接调用写工具。未配置时如实显示指令模式，不假装具备自由对话能力。
3. 用户提供门店名或主动授权一次定位。当前实时门店 schema 没有经纬度字段：浏览器定位先反向地理编码，再用 searchType=2、city、keyword 查询。不要按过时文档发送 searchType=3；不读取收藏、历史订单、配送地址。由用户选择真实门店，不能擅自把搜索首项当成所在门店。
   实测城市虽未在 schema 中标为必填，缺失时业务返回600058；先追问城市，保留门店名和餐品需求。只读失败允许用户发“重试”重新执行，不用模型话术代替真实查询。
4. 读取菜单，结合口味与可选预算推荐真实餐品。菜单中的 frequent 不建画像、不送给模型。查详情，套餐使用 isDefault=1 的真实默认项，特调用 selectedKey/unselectedKey；缺少必选默认项时问用户。换饮料、去冰等须匹配详情里的真实可选项，不能把没满足的要求悄悄丢弃。过敏或交叉接触风险需门店核实，模型不能保证安全。
5. 调用 calculate-price，价格为整数分。展示门店、餐品、份数、套餐子项、费用、最终应付金额及取餐方式；takeWayCode 必须取自 takeWayList，多个方式由用户选择。定时制作、取消规则未知时直说。不自行领券、购会员或加入随单购。
6. 明确展示当前订单后，用户回复“确认下单”或点击绑定当前预览的确认按钮，才调用现有 ConfirmationLedger 执行 create-order。模型输出、历史聊天确认和点击过期按钮均不能授权。确认前再次官方算价；价格、搭配、费用变化必须重展示并再确认。
7. 创建后只显示“待支付”和官方返回的 payH5Url，由用户在官方收银台完成付款。没有代扣接口，不声称能在聊天中无感扣款。用户发“订单状态”后用已知 orderId 查询，取餐码及付款状态来自官方数据。

## 微信与定位

详细接入见 [weixin-integration.md](references/weixin-integration.md)。公开协议的 Python 兼容桥接只回复扫码绑定者的新消息，不发群、不主动联系其他人。已转写的语音按文字理解，不宣称已实现独立语音识别。

个人微信通道未暴露原生位置消息。用户在微信发“定位”，使用独立 HTTPS 单次定位页，授权后回微信选择门店。定位通道只代理本机8766端口，禁止代理主应用8765端口；模型密钥和后台绝不能通过隧道公开。令牌单次使用、5分钟失效。关闭定位通道不影响按门店名点餐。

## 一致性和恢复

沿用本地 SQLite 确认台账；它不等于供应商服务端幂等。写请求前原子锁定，超时或响应缺失保留 unknown；不得换 scope、刷新、重启或另开会话绕过。没有 orderId 的未知提交需用户先在官方客户端核查。确认前仅查询，不为演示创建真实测试订单。

浏览器 cookie 经项目内密钥签名，重启可恢复已知订单号；微信以绑定者身份隔离状态。聊天内容与精确坐标不落盘；模型设置和微信凭证文件权限600。模型错误不得回显供应商响应正文或密钥。

## 口味、别名与账户

“穷鬼套餐”按用户约定映射1+1超值／随心配系列，再匹配当前门店真实商品，不保证固定价格或擅自把两个单品当优惠。只有点餐意图由模型解析；长期偏好写入由服务端从明确第一人称饮食表述或真实餐品选择中提取。长期记忆只保存饮食标签、受约束别名和选择次数，支持查看、忘记、清除、停用；本次明确要求优先，多次选择不等于已购买。详见 [memory-and-context.md](references/memory-and-context.md)。

微信绑定与麦当劳账号授权独立。使用当前 MCP Token 所授权的麦当劳账号；查询积分或优惠券需用户主动要求，资产明细不送语言模型、不进入偏好库。官方查询积分成功不等于已取得完整个人资料或代扣权限。不得为学习偏好自动扫描历史订单。

## 文件与验证

- scripts/ordering_agent.py：微信与网页共用的点餐状态机。
- scripts/model_gateway.py：千问／DeepSeek 兼容接口，真实菜单编码验证。
- scripts/location_service.py、location_relay.py：授权定位和独立单次手机定位页。
- scripts/confirmation.py：本地确认台账；CLI 高级操作仍经 prepare / confirm，不能绕过。
- [agent-redesign.md](references/agent-redesign.md)：本次产品方向与能力边界。

验证使用项目解释器，TMPDIR、pytest --basetemp 和 cache_dir 都设在 runtime。改过点餐状态机需检查：无预算点餐、默认套餐、换饮料、取餐方式、价格变化、过期预览、重复确认、未知结果跨会话恢复，以及网页/微信共用引擎。未经本轮具体授权不做真实消费测试。
