# 麦合拍 MaiMate · 你的饭搭子

微信里的到店点餐智能体，本机网页提供管理后台与可选调试聊天。支持真实门店与菜单、千问／DeepSeek 自然语言理解、套餐换搭配、官方算价、确认后创建订单、官方收银台付款，以及订单状态与取餐码查询。

## 开始使用

首次克隆请先按根目录 README 创建项目内 Conda 环境并复制空凭证模板。已有环境位于 .conda/，麦当劳 key 由后端从 .env 读取。

    cd MaiMate/麦合拍MaiMate
    ./maimate.sh start

- 管理后台：http://127.0.0.1:8765/
- 调试聊天：http://127.0.0.1:8765/chat
- 模型与定位设置：http://127.0.0.1:8765/settings
- 个人微信连接：http://127.0.0.1:8765/weixin

在设置页选择千问或 DeepSeek，填写 API key，保存并测试即可。默认中国内地千问接口 / qwen-plus、DeepSeek 官方接口 / deepseek-chat；模型名可改。配置实时生效，无需重启。key 不回显，保存在项目 runtime/model.json，权限600。也可通过本项目 .env 的 LLM_PROVIDER、LLM_MODEL、LLM_API_KEY 配置；页面配置优先。

模型会收到本次对话和必要菜单、选配信息，不会收到麦当劳 Token、微信凭证、完整历史订单或完整账户资料。无模型 key 时可用明确指令选店、套餐、换选项，但不是完整自然语言能力。

“保存并测试”会验证微信／网页实际使用的结构化点餐工具调用与本地意图校验。DeepSeek 点餐请求显式关闭思考模式，以兼容强制 `order_intent` 调用；无需因此更换已配置的 key 或模型。接口错误按参数、认证、余额和限流分别提示，不回显供应商原文。

## 到店后直接说需求

“我在某城市某门店，今天赶时间，你帮我挑一份牛肉的，饮料无糖，打包。”

智能体保留本单约束，结合中国本地时间、当前状态、口味证据和真实菜单选餐。完整门店名唯一匹配时直接验证并读取菜单；地标或多个结果仍需选店。明确委托后自动搭配和算价，直接给出预览，缺少必选项或取餐方式才问。点名餐品优先，绝不被历史喜好替换。

看到当前门店、搭配和金额后回复“确认下单”，再到官方收银台付款。查进度发“订单状态”，另买一单发“重新点餐”。查积分、历史或营业状态和聊天均不需要退出当前点餐。

本项目没有代扣 API。订单未支付、已支付、配餐中等状态严格区分。算价与创建之间没有库存锁定或原子价格版本，不保证官方服务器端幂等。

## 自动定位与微信

浏览器定位需要系统授权。为适配当前官方 city/keyword schema，使用 Photon（备用 Nominatim）的 OpenStreetMap 数据将 WGS84 坐标转成城市和地标，再查门店。解析结果只在内存缓存，每秒最多一次请求，不做自动补全。定位不可用时可发门店名，不拿 IP 或默认城市冒充位置。

个人微信协议未暴露原生位置消息。设置页启用微信定位后，在微信发“定位”；打开单次链接授权，查看门店列表，回微信回复“选店1”。令牌单次使用、5分钟到期。

Cloudflare 官方组件位于 runtime/bin，通过 GitHub 官方 release SHA256 校验。重装：

    TMPDIR="$PWD/runtime/tmp" PYTHONDONTWRITEBYTECODE=1 .conda/bin/python maimate/scripts/install_location_tunnel.py

隧道只指向独立127.0.0.1:8766接收器；后台8765仍仅本机访问。临时隧道没有可用性保证，部分网络或微信浏览器可能拦截，可在系统浏览器打开或发门店名继续。重启后需重新开启通道。没有修改全局 OpenClaw、Conda 或系统代理配置。

微信桥接遵循腾讯公开协议，见 maimate/references/weixin-integration.md。只回复扫码绑定者的新文字或已转写语音，不接群。`./maimate.sh start` 在后台运行并恢复已有绑定；前台调试启动默认暂停，可在连接页恢复；电脑休眠、断网或服务退出时无法接收。

## 本地数据与确认

### 越用越懂你的口味

在微信说“记住，我喜欢无糖饮料，也爱吃薯条”。套餐昵称没有预置映射，选店后可说“昵称就是菜单中的餐品名”；只保存可核实的唯一目标。也可在点餐时说明“我要某餐品（即我的昵称）”。明确口味和多次选餐会影响后续推荐；“今天想换牛肉”“今天要普通可乐”等本次要求优先，不因一次点餐永久覆盖习惯。

发“我的偏好”查看，“忘记无糖”删除单项，“清除偏好”全部删除，“关闭记忆”停止学习和使用。微信连接页也可查看和管理。结构化偏好仅保存在项目 `runtime/dining-memory.sqlite3`，权限600；不保存完整聊天、健康信息或精确位置，历史订单只在主动要求分析或点击后台导入时读取，不定时扫描。

微信页新增最近20轮脱敏对话，方便核对异常；只在本次服务内存中，重启清空，无法拉取微信旧聊天。只读接口失败后可发“重试”，会实际执行该查询；创建订单不会被重放。

### 麦当劳账号与微信账号

点餐使用申请当前 MCP Token 时授权的麦当劳账号，微信扫码只是收发入口，不会切换麦当劳账号。发“账号说明”了解授权，“我的积分”或“我的优惠券”按需读取资产；账户资产不发送给模型或保存进偏好库。当前接口不提供完整个人档案、手机号或会员等级，官方付款页是否需要验证以页面为准。

所有新文件、依赖、缓存、临时数据和凭证只在本项目内：

- .env：麦当劳 key，不公开、不记录到日志。
- runtime/model.json：模型配置，不回显密钥。
- runtime/weixin/：绑定、游标、消息哈希去重。
- runtime/confirmations.sqlite3：请求哈希、预览确认、提交状态、已知订单号；不存原始聊天。
- runtime/web-session.key：本机浏览器会话签名。
- runtime/location/、runtime/bin/：定位隧道、日志、组件。

确认前后官方算价；换搭配、换店、过期或金额变化使旧确认失效。写请求前原子记录 in_flight，未知结果保持锁定。没有订单号时在官方客户端核查，不删除台账或换会话绕过。通用 CLI 禁止直接调用写工具。

## 饭搭子与口味手记

现在可先聊天再点餐；连接千问或 DeepSeek 后，智能体用最近对话和必要的口味摘要承接上下文。重启后仅恢复结构化口味，不虚构旧聊天或共同经历。普通聊天不会执行订单操作，换餐理解失败仍会撤销旧预览的确认资格。

`/memory` 是口味手记：明确喜好有来源与更新时间；多次选择是弱信号；餐后评价单独保存，最近90天逐渐减弱。发“评价上一餐”先核对餐品，再发“这餐好吃”“这餐一般”“这餐不喜欢”；网页评价按钮绑定当次选餐，过期按钮不能评价新的餐品。同次选餐可修改一次评价，不因重复点击增加样本。评价和选择不代表实际付款。发“口味复盘”查看趋势，“为什么推荐”查看当前推荐依据。

“按老样子推荐”参考已有口味；“换换口味”降低熟悉餐品的优先级。模型给的顺序不再覆盖本地偏好评分。本次明确指定和排除的肉类优先，反馈不会永久覆盖明确喜好。学习仅更新本地结构化数据和排序，没有训练或自动修改模型。

原有偏好数据库和确认台账沿用，旧网页签名Cookie会迁移为新名称，保留相同操作者身份和订单恢复能力。目录更名后，本机保留被忽略的旧环境路径兼容链接；凭证、绑定与运行数据没有重新生成。新克隆按根目录README创建环境即可。

## 历史订单分析与后台运行

首页是管理后台：微信/模型/MCP连接、常点清单、月份金额、时段、偏好来源和按需积分查询；`/chat` 用于调试。进入后台不会自动读取官方历史或资产。

“分析历史订单”触发 `order-list` 一次，无分页参数、不追读详情；本次最多分析返回的前30条，纳入近90天且文本状态明确完成的去重订单。取消、未付、数字等未核实状态、无效日期或金额排除。实付金额按元解析，内部使用整数分。餐品按完成订单出现次数统计，不把份数或套餐子项重复计入偏好，也不假定全由你本人消费。

本机 `runtime/dining-insights.sqlite3` 只保存汇总，按操作者和当前MCP凭证散列隔离；更换凭证不复用旧分析。重复餐品可作为弱推荐依据，不覆盖明确喜欢/不喜欢；导入30天后停止参考直至再次手动更新。模型只收到重复餐品名、次数与来源，不接收订单号、金额、门店、日期和积分。`清除历史订单分析` 删除该来源，`清除偏好` 同时删除全部来源；`忘记餐品` 排除该历史餐品及后续导入中的相应名称，`关闭记忆` 停止所有长期口味使用。

`./maimate.sh start` 后台启动，`status` 检查，`stop` 停止，`restart` 重启，`open` 打开管理台。macOS可双击 `启动麦合拍.command`。配置、日志、锁和PID都在项目runtime，不写系统开机服务；机器在线才能回复微信，定位隧道不会自动开启。

“这家店人多吗/营业吗”会刷新已选店的营业状态和时间；没有当前城市与门店时先补充。官方未提供客流、空座和排队人数，不据时间或营业状态伪造实时拥挤度。
